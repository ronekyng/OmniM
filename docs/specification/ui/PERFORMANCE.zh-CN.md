# OmniM 界面性能预算

> **契约范围。** 本文固定参考机、启动与交互预算、渲染与内存预算、包体上限、大列表行为与回归门禁。它是需求 `UI-PRF-01` … `UI-PRF-08` 的规范来源。
>
> **双轨维护义务**：`PERFORMANCE.zh-CN.md` 是持续维护的译文。在同一次变更中保持章节编号、数字与需求 ID 一致。
>
> **状态。** 设计契约。目前没有预算被强制执行；基线记录在 [FRONTEND_BASELINE](../../status/FRONTEND_BASELINE.zh-CN.md)。

## 1. 目的与方法

性能是产品需求，因为工程模型很大，而用户会先注意到延迟，再注意到功能。预算只有在有数字、有机型、有门禁时才算数。

方法：

1. 每个预算都在参考机（§2）上用固定夹具测量。
2. 除特别说明外，数字为五次运行的 p95。
3. 回归相对 `web/tests/perf/baseline.json` 中的基线衡量。
4. 预算变更需要记录决策，不允许静默修改。

## 2. 参考机

| 部件 | 规格 |
|---|---|
| CPU | 8 核 x86-64，基准 3.2 GHz |
| 内存 | 16 GB |
| GPU | 集成或入门独显，支持 WebGL2 |
| 显示器 | 1920×1080，DPI 100% |
| 浏览器 | Chromium 最新稳定版 |
| 服务 | 同机，本地回环 |
| 夹具 | `fixtures/perf/office-2000.omnim`（2000 个对象） |

本文所有数字都假设该机型。较慢机器在发布说明中给出按比例的宽容度，绝不静默放行。

## 3. 启动与交互预算

| 指标 | 预算 | 测量 |
|---|---|---|
| 首次内容绘制 | ≤ 1.2 s p95 | 导航计时 |
| 首次有意义绘制（工作区外壳） | ≤ 2.5 s p95 | 外壳挂载后的自定义标记 |
| 工作区就绪（视口可交互） | ≤ 4.0 s p95 | 首帧渲染后的标记 |
| 打开项目（2000 对象） | ≤ 3.0 s p95 | 从点击到可交互 |
| 需求 | UI-PRF-01 |

### 3.2 交互延迟

| 交互 | 预算 |
|---|---|
| 按钮/开关反馈 | ≤ 100 ms |
| 面板/标签切换 | ≤ 150 ms |
| 选择高亮 | ≤ 100 ms |
| 单对象属性面板渲染 | ≤ 120 ms |
| 命令面板打开 | ≤ 120 ms |
| 上下文菜单打开 | ≤ 100 ms |
| 需求 | UI-PRF-02 |

**规则：** 超过 300 ms 的操作需要进度指示（见 [FEEDBACK_ERRORS](FEEDBACK_ERRORS.zh-CN.md) §4），而不是更久的加载动画。

## 4. 渲染预算

### 4.1 帧率

| 场景 | 目标 | 下限 |
|---|---|---|
| 500 对象，轨道旋转 | 60 fps | 45 fps |
| 2000 对象，轨道旋转 | 45 fps | 30 fps |
| 2000 对象，静止 | 60 fps | 30 fps |
| 5000 对象，静止（按楼层过滤） | 30 fps | 20 fps |

帧时间在渲染循环上测量，超过 50 ms 的 GC 尖峰单独报告。

### 4.2 场景规模

| 规则 | 取值 |
|---|---|
| 重复目录实例 | 超过 50 个相同网格必须使用实例化 |
| 屏幕外对象 | 剔除；完全裁掉的楼层不产生绘制调用 |
| 剖切 | 使用裁剪平面，不在 CPU 上逐三角形处理 |
| 阴影贴图 | 最大 2048²，按需更新 |

### 4.3 空闲行为

| 指标 | 预算 |
|---|---|
| 空闲 CPU（无输入、无动画） | < 单核 1% |
| 空闲 GPU | 无持续重绘 |
| 需求 | UI-PRF-04 |

**规则：** 渲染循环必须按需驱动；无条件 `requestAnimationFrame` 循环属于缺陷。

需求：UI-PRF-03。

## 5. 内存

| 指标 | 预算 |
|---|---|
| 工作区就绪后基线 | ≤ 350 MB |
| 2000 对象 | ≤ 800 MB |
| 5000 对象 | ≤ 1.5 GB |
| 8 小时会话增长 | 相对基线 ≤10% |
| 撤销/重做 500 次后的几何 | 无无界增长 |

测量：Chromium 堆快照，每 60 秒采样 `performance.memory`。需求：UI-PRF-05。

## 6. 包体

| 资源 | 预算 |
|---|---|
| 初始 JS（gzip） | ≤ 500 KB |
| 初始 CSS（gzip） | ≤ 60 KB |
| Three.js 分块 | 懒加载，随视口路由加载 |
| 编辑器路由 | 独立分块 |
| 字体 | ≤ 2 个字族，子集化，`font-display: swap` |
| 需求 | UI-PRF-06 |

规则：任何 gzip 后超过 50 KB 的库都需要记录决策；禁止图标字体（使用 SVG）。

## 7. 大列表

| 列表 | 规模 | 技术 | 预算 |
|---|---|---|---|
| 对象树 | 5000 节点 | 虚拟化 | 滚动 ≥50 fps |
| 属性表 | 500 行 | 虚拟化或分页 | 滚动 ≥50 fps |
| 构件库 | 1000 个构件 | 窗口化网格 | 筛选响应 ≤200 ms |
| 控制台输出 | 10000 行 | 环形缓冲 | 追加 ≤16 ms |

需求：UI-PRF-07。

## 8. 回归门禁

| 规则 | 取值 |
|---|---|
| 基线文件 | `web/tests/perf/baseline.json`，随代码提交 |
| 容差 | p95 ±10%，内存 ±15% |
| 失败 | CI 让性能任务失败并阻塞合并 |
| 噪声控制 | 五次运行取中位数；丢弃第一次预热 |
| 环境漂移 | 基线记录参考机指纹 |
| 需求 | UI-PRF-08 |

**例外流程：** 超出容差的回归需要在 PR 中写明理由，并建一个带责任人与日期的后续 issue。

## 9. 测量工具

| 层次 | 工具 |
|---|---|
| 导航与标记 | `PerformanceObserver`、自定义标记 |
| 帧时间 | `requestAnimationFrame` 差值，5 秒窗口 |
| 内存 | Chromium 堆快照，可用时用 `measureUserAgentSpecificMemory` |
| 包体 | Vite 构建报告、size-limit 检查 |
| CI | 参考机运行器上的 Playwright 性能项目 |

## 10. 非目标

1. 集成显卡上的亚 16 ms 交互保证。
2. 移动端性能目标。
3. 云托管模型的网络传输优化。
4. 与离线渲染器对齐的渲染质量。
