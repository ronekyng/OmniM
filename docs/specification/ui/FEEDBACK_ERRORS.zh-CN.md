# OmniM 界面反馈与错误契约

> **契约范围。** 本文固定面板状态、长操作反馈、错误模型、错误边界、提示消息与诊断包。它是需求 `UI-FBK-01` … `UI-FBK-10` 的规范来源。
>
> **双轨维护义务**：`FEEDBACK_ERRORS.zh-CN.md` 是持续维护的译文。在同一次变更中保持章节编号、错误码规则与需求 ID 一致。
>
> **状态。** 设计契约。原生弹窗已移除（`ConfirmDialog` + `notify`），错误边界覆盖应用、工作区与每个面板槽位；加载/空/错误三态完整性与抛错面板测试仍待补。见 [CODE_DEVIATIONS §7](../../status/CODE_DEVIATIONS.zh-CN.md)。

## 1. 目的

商业软件从不把用户留在猜测里。每次等待、每次失败、每次成功都必须可见、可归因、可操作。

## 2. 反馈层级

| 层级 | 时延 | 机制 | 是否打断工作 |
|---|---|---|---|
| 即时 | < 100 ms | 悬停、按下、焦点环 | 否 |
| 瞬时 | 100 ms – 1 s | 控件内联加载、乐观状态 | 否 |
| 进度 | > 1 s | 带阶段标签与取消的进度条 | 否 |
| 结果 | 完成时 | 提示消息（成功/信息）或横幅（警告） | 否 |
| 阻断 | 无法继续 | 带恢复动作的弹窗 | 是 |
| 环境 | 持续状态 | 状态栏槽位 + 横幅 | 否 |

**规则：** 同一事件不得产生两条竞争信息（例如一次保存同时弹出提示和横幅）。

## 3. 面板状态

### 3.1 加载

- 面板首次加载：与最终布局匹配的骨架屏。
- 后续加载：保留旧内容并显示顶部细进度线（不产生布局位移）。
- 绝不用整屏 spinner 替换整个工作区。

### 3.2 骨架屏时序

| 延时 | 行为 |
|---|---|
| < 400 ms | 不显示任何加载态，直接出结果 |
| 400 ms – 3 s | 骨架屏 |
| > 3 s | 骨架屏 + 阶段标签 + 安全时提供取消 |

需求：UI-FBK-02。

### 3.3 空状态

每个空状态回答三个问题：为什么空、我能做什么、如何了解更多。

| 面板 | 主操作 |
|---|---|
| 对象树 | 创建对象，或打开示例项目 |
| 属性（无选择） | "在视口或树中选择一个对象" |
| 构件库（无结果） | 清除筛选 |
| 轴网 | 添加轴网 |
| 控制台 | 显示示例命令 |
| 最近项目 | 新建项目 |

需求：UI-FBK-01, UI-FBK-09。

### 3.4 错误

面板级错误就地渲染，保留面板外框，并提供重试与详情。绝不能让外壳白屏。需求：UI-FBK-01。

## 4. 长操作

| 操作 | 进度 | 取消 | 说明 |
|---|---|---|---|
| IFC 导入 | 解析、映射、重建三阶段 | 提交前可取消 | 取消即回滚 |
| IFC 导出 | 序列化阶段 | 否（很快） | 完成后下载 |
| 全部特征重建 | 按特征计数 | 特征之间可取消 | 部分状态必须明确 |
| 目录导入 | 解析、校验 | 提交前可取消 | 不允许半套图库 |
| 另存为 | 写入阶段 | 否 | 服务端原子写 |

规则：

1. 进度报告阶段与计数，尽量不报虚假百分比。
2. 取消必须让模型回到操作前状态，或明确标注部分结果。
3. 界面保持可交互；视口不被遮罩锁死。

需求：UI-FBK-03。

## 5. 错误模型

### 5.1 错误码格式

```text
OMNI-<AREA>-<NNNN>
  AREA: UI | API | NET | IO | GEO | CAT | IFC | AUTH | SYS
  NNNN: 四位补零序号，永久稳定
```

示例：`OMNI-NET-0003`（服务不可达）、`OMNI-GEO-0012`（退化边界）、`OMNI-IFC-0007`（不支持的实体）。

规则：错误码永不复用；退役码永久保留；错误码是界面文案、错误目录与遥测之间的连接键。

### 5.2 文案结构

每条用户可见错误包含四部分：

1. **标题** —— 用用户的语言说明什么失败了。
2. **原因** —— 一句话说明最可能的原因。
3. **恢复** —— 下一步动作（按钮或说明）。
4. **详情** —— 错误码、HTTP 状态、请求 ID；可展开、可复制。

示例：

> **无法保存项目。** 服务端拒绝了写入（`OMNI-IO-0004`，HTTP 500）。你的修改仍在内存中。[重试] [另存为…] [复制详情]

### 5.3 严重度

| 严重度 | 含义 | 呈现 | 遥测 |
|---|---|---|---|
| 阻断 | 无法继续 | 弹窗 | error 事件 |
| 降级 | 功能不可用，应用仍可用 | 横幅 | warn 事件 |
| 可恢复 | 操作失败，可重试 | 内联 + 错误提示 | error 事件 |
| 信息 | 预期内的拒绝（校验） | 字段内联错误 | 无 |
| 未预期 | 未捕获异常 | 错误边界 | error 事件 + 堆栈 |

### 5.4 错误目录

`docs/reference/ERROR_CODES.md` 是人工维护的目录。`scripts/check_ui_contracts.py --only errors` 在源码使用目录之外的 `OMNI-*` 码时失败。

需求：UI-FBK-04, UI-TLM-03。

## 6. 原生弹窗禁令

应用代码中禁止：

- `window.alert`
- `window.confirm`
- `window.prompt`

替代：`ConfirmDialog`、`PromptDialog` 与内联校验模式。

`scripts/check_ui_contracts.py --dialogs` 报告每处调用；只要仍有残留，`--strict --dialogs` 就让构建失败。

需求：UI-FBK-05。

## 7. 错误边界

| 边界 | 范围 | 兜底 |
|---|---|---|
| 根 | 整个应用 | 全页错误，提供重载与诊断导出 |
| 路由 | 工作区、各编辑器 | 路由外壳 + 面包屑 + "返回工作区" |
| 面板 | 每个注册面板 | 面板外框 + 重试；其他面板不受影响 |
| 视口 | 3D 画布 | 画布占位 + 渲染错误 + 重载场景 |

规则：

1. 边界使用关联 ID 写入诊断缓冲区。
2. 兜底不得隐藏导航外壳。
3. 同一面板在一次会话中重复失败时，关闭自动重试并提供诊断。

需求：UI-FBK-06。

## 8. 提示消息

### 8.1 类型

| 类型 | 存活时间 | 可关闭 | 示例 |
|---|---|---|---|
| 成功 | 4 s | 是 | "Wall-003 已创建" |
| 信息 | 6 s | 是 | "布局已重置" |
| 警告 | 8 s 或直到关闭 | 是 | "该工具下已禁用捕捉" |
| 错误 | 直到关闭 | 是 | "保存失败——修改保留在内存中" |

### 8.2 位置

| 规则 | 取值 |
|---|---|
| 锚点 | 视口右下角，状态栏之上 |
| 堆叠 | 最多 3 条可见；更早的折叠为计数 |
| 宽度 | 320–420 px |
| 安全区 | 不得遮挡视图立方、工具条或剖切手柄 |
| 动效 | 150 ms 滑入；`prefers-reduced-motion` 下禁用 |

需求：UI-FBK-07, UI-FBK-08。

### 8.3 去重

2 秒内相同消息合并为一条并计数。错误不得仅按类型合并——每个对象级失败都要指出对象。

## 9. 诊断包

| 内容 | 包含 | 不包含 |
|---|---|---|
| 应用版本与构建哈希 | 是 | — |
| 服务版本与路由表哈希 | 是 | — |
| 浏览器、GPU、WebGL 能力 | 是 | — |
| 最近 500 行日志 | 是 | 文件内容 |
| 最近 100 条命令（ID、时间、结果） | 是 | 几何、用户对象名称 |
| 项目元信息 | 仅名称与单位制 | 对象数据 |
| 截图 | 可选，需用户确认 | 自动捕获 |

格式：单个 `.zip`，含 `manifest.json`、`logs.txt`、`commands.json`、`environment.json`。需求：UI-FBK-10, UI-TLM-05。

## 10. 非目标

1. 未经同意的自动崩溃上传。
2. 面向最终用户的日志浏览器（诊断包之外）。
3. 本地化堆栈信息。
