# OmniM UI Accessibility Contract

> **Contract scope.** This document fixes the accessibility target, WCAG mapping, keyboard completeness, focus management, semantics, alternatives, motion, high contrast, and live announcements. It is the normative source for requirements `UI-A11Y-01` … `UI-A11Y-08`.
>
> **Dual-track maintenance obligation**: `A11Y.zh-CN.md` is a maintained translation. Keep section numbering, WCAG references, and requirement IDs aligned in the same change.
>
> **Status.** Design contract. Current coverage is one `aria-*` attribute and zero `role` attributes across the client; see [FRONTEND_MATURITY](../../status/FRONTEND_MATURITY.md).

## 1. Purpose and Target

**Target: WCAG 2.2 Level AA on all critical paths**, plus EN 301 549 alignment for procurement.

Critical paths are: first run, project open, object creation, selection and properties, save, and error recovery. A path is compliant only when both automated and manual keyboard/screen-reader checks pass.

Accessibility is not a separate mode: the default UI must already be usable without a mouse, and the high-contrast theme is an additional aid.

## 2. WCAG 2.2 AA Mapping

| WCAG success criterion | Applies to | Contract implementation |
|---|---|---|
| 1.3.1 Info and Relationships | Trees, tables, docks | Semantic roles and headings (§5) |
| 1.4.1 Use of Color | Selection, status, errors | Color plus icon/text; never color alone |
| 1.4.3 Contrast (Minimum) | All text | Token pairs audited at 4.5:1 |
| 1.4.11 Non-text Contrast | Borders, focus rings, viewport selection | 3:1 against adjacent colors |
| 1.4.12 Text Spacing | Panels | Layout tolerates 1.5× line height |
| 2.1.1 Keyboard | All commands | Keyboard registry coverage (§3) |
| 2.1.2 No Keyboard Trap | Dialogs | Traps are intentional and escapable (§4) |
| 2.4.3 Focus Order | Workspace | DOM order matches visual order |
| 2.4.7 Focus Visible | All controls | 2 px ring, token-driven |
| 2.4.11 Focus Not Obscured | Docked panels | Focused element never hidden by overlays |
| 2.5.7 Dragging Movements | Splitters, section handle | Keyboard alternatives provided |
| 3.2.2 On Input | Forms | No navigation on value change |
| 3.3.1 Error Identification | Forms, operations | Code + message + recovery (§[FEEDBACK_ERRORS](FEEDBACK_ERRORS.md) §5) |
| 4.1.2 Name, Role, Value | All components | Component contract ([DESIGN_SYSTEM](DESIGN_SYSTEM.md) §9) |
| 4.1.3 Status Messages | Toasts, save state | `aria-live` (§9) |

Requirement: UI-A11Y-01.

## 3. Keyboard Completeness

| Rule | Value |
|---|---|
| Coverage | Every command reachable without a pointer |
| Discovery | `F1` opens the shortcut reference; every command palette row shows its shortcut |
| Traversal | `Tab` moves between regions; `F6` cycles regions (menu, ribbon, left dock, viewport, right dock, bottom dock, status) |
| Trees | Arrow keys navigate; `←`/`→` collapse/expand; `Enter` activates; `F2` renames |
| Tables | Arrow keys move cells; `Enter` edits; `Esc` cancels the edit |
| Viewport | All view commands available via the ribbon and palette |
| Requirement | UI-A11Y-02 |

**Proof:** a keyboard-only walkthrough script completes J1 (create and save) without a pointer.

## 4. Focus Management

| Event | Behavior |
|---|---|
| Region change (`F6`) | Focus moves to the region's first focusable element |
| Panel tab switch | Focus stays on the tab; content is reachable with `Tab` |
| Dialog open | Focus to the first meaningful control; background inert |
| Dialog close | Focus returns to the invoker |
| Toast | Never steals focus |
| Error boundary | Focus to the fallback heading, announced |
| Route change | Focus to the page `<h1>` |

Rules:

1. Focus is always visible: 2 px ring, offset 2 px, using `--focus-ring`.
2. `:focus-visible` is used for pointer interactions so mouse clicks do not show rings.
3. Removing an element that holds focus moves focus to a documented neighbour, never to `<body>`.

Requirement: UI-A11Y-03.

## 5. Semantics and ARIA

| Component | Role | Required states |
|---|---|---|
| Object tree | `tree` / `treeitem` | `aria-expanded`, `aria-selected`, `aria-level` |
| Property table | `table` with `row`/`columnheader`/`cell` | `aria-rowcount`, `aria-colcount` |
| Dock tabs | `tablist`/`tab`/`tabpanel` | `aria-selected`, `aria-controls` |
| Ribbon group | `toolbar` | `aria-label`, `aria-orientation` |
| Dialog | `dialog` + `aria-modal="true"` | `aria-labelledby`, `aria-describedby` |
| Menu | `menu`/`menuitem` | `aria-haspopup`, `aria-expanded` |
| Toast region | `status`/`alert` | `aria-live` |
| Viewport | `application` or `img` with description | `aria-label`, `aria-describedby` |

Rules:

1. No `role` without the matching keyboard behavior.
2. `aria-label` text is localized and comes from the i18n catalogue.
3. Decorative icons use `aria-hidden="true"`; meaningful icons live inside a named button.

Requirement: UI-A11Y-04.

## 6. Names and Alternatives

| Element | Accessible name source |
|---|---|
| Icon button | `aria-label` from the command label |
| Number field | Visible label + unit in the description |
| Viewport | Summary of visible object count, active storey, and camera mode |
| Canvas-only content | Text alternative in the Properties panel and a "describe scene" action |
| Status bar | Individual slots with labels, not one concatenated string |

Requirement: UI-A11Y-05.

## 7. Motion and Contrast Preferences

| Preference | Behavior |
|---|---|
| `prefers-reduced-motion: reduce` | Remove panel slide/fade, view cube easing, toast animation; keep opacity changes ≤ 100 ms |
| `prefers-contrast: more` | Apply the high-contrast theme automatically on first run |
| `forced-colors: active` | Respect system colors; disable custom shadows and gradients |

Requirement: UI-A11Y-06.

## 8. High Contrast Theme

| Rule | Value |
|---|---|
| Activation | Manual in settings, or automatic under `prefers-contrast: more` |
| Background | `#000000`, text `#ffffff` |
| Accents | Saturated, ≥ 4.5:1 on black |
| Borders | 1 px minimum, visible at 3:1 |
| Focus | 2 px, `#ffffff` with a 1 px black inner ring |
| Shadows | Disabled |
| Icons | Stroke 1.5 px minimum, never thin-line only |
| Requirement | UI-A11Y-07 |

## 9. Live Announcements

| Event | Message | Politeness |
|---|---|---|
| Object created | "{name} created" | polite |
| Selection changed | "{type}, {name}" or "{n} objects selected" | polite |
| Save completed | "Project saved at {time}" | polite |
| Save failed | "Save failed: {cause}. Changes kept in memory." | assertive |
| Error boundary | "This panel failed to load. {recovery}" | assertive |
| Progress milestone | "{phase}, {percent}%" | polite, throttled 2 s |

Rules: one live region per severity, never reused for toasts; messages are localized; rapid events are coalesced.

Requirement: UI-A11Y-08.

## 10. Testing and Evidence

| Layer | Tool | Gate |
|---|---|---|
| Automated rules | axe-core in Playwright on critical paths | G2 |
| Keyboard | Manual scripted walkthrough, recorded | G2 |
| Screen reader | NVDA (Windows) and VoiceOver (macOS) spot checks | G2 |
| Contrast | Token audit script in both themes | G2 |
| Conformance artifact | Accessibility Conformance Report (ACR/VPAT) draft | G3 |

**Rule:** an accessibility bug that blocks a critical path is release-blocking at every gate.

## 11. Non-Goals

1. WCAG 3.0 conformance.
2. Full screen-reader support for 3D spatial manipulation.
3. Audio alternatives for modeling operations.
4. Cognitive accessibility certification beyond AA.
