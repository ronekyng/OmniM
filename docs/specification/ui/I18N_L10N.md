# OmniM UI Internationalization and Localization

> **Contract scope.** This document fixes string externalization, locale selection, ICU formatting, number/date/unit handling, pseudo-localization, key hygiene, RTL readiness, and the translation workflow. It is the normative source for requirements `UI-I18N-01` … `UI-I18N-07`.
>
> **Dual-track maintenance obligation**: `I18N_L10N.zh-CN.md` is a maintained translation. Keep section numbering, key examples, and requirement IDs aligned in the same change.
>
> **Status.** The §3/§4/§5 kernel is delivered (2026-11-03, Phase 8-5 batch): `web/src/shared/i18n.ts` (`t()`/`tPlural()`/`useI18n()` + `Intl.PluralRules` and number/date/time/angle formatters), the `web/src/shared/i18n/{zh-CN,en-US}.ts` dictionaries, `omnim.locale` persistence with `<html lang>` sync, and `e2e/language.spec.ts`. §2 string extraction (UI-I18N-01) is still in progress: the title bar / leave-confirm batch is externalised; the remaining high-frequency surfaces (status bar, panels, creation forms) are not migrated yet.

## 1. Purpose and Scope

OmniM ships to Chinese- and English-speaking engineering teams. Localization is therefore a product capability, not a translation afterthought.

In scope: the browser client's UI strings, number/date/unit presentation, language switching, and locale-aware validation messages.

Out of scope: model data, file formats, IFC entity names, and server log messages.

## 2. String Externalization

| Rule | Value |
|---|---|
| Coverage | 100% of user-visible strings, including `aria-label`, `title`, placeholder, toast, error, and empty-state text |
| Source of truth | `web/src/shared/i18n/<locale>.ts`; one catalogue per locale |
| Access | `useI18n()` hook or `t('key')`; no string concatenation |
| Prohibited | Chinese or English literals inside `.tsx` outside the catalogue |
| Dynamic text | ICU placeholders; never string arithmetic |
| Server strings | Mapped through error codes, not displayed raw |
| Requirement | UI-I18N-01 |

Enforcement: `scripts/check_ui_contracts.py --strings` scans `.tsx`/`.ts` for CJK literals outside `i18n/`; `--strict --strings` fails the build. **Limitation:** the scan detects CJK only — hardcoded English JSX text is not yet detected (📅 `UI-I18N-01`).

## 3. Locale Selection and Fallback

| Rule | Value |
|---|---|
| Supported locales | `zh-CN` (default), `en-US` |
| Detection order | Stored user choice → `navigator.languages` intersection → `zh-CN` |
| Fallback | Missing key falls back to `en-US`, then renders the key itself in development only |
| Switching | Immediate, no reload; persists in `localStorage` (`omnim.locale`) |
| Document attributes | `<html lang>` updates on switch |
| Formats | Locale switch also re-renders numbers, dates, and units |
| Requirement | UI-I18N-02 |

**Rule:** a missing key in production renders the `en-US` value and logs a diagnostic event; it never shows `undefined` or a raw key.

## 4. Message Formatting (ICU)

| Need | Pattern |
|---|---|
| Plural | `{count, plural, =0 {No objects} one {# object} other {# objects}}` |
| Select | `{type, select, wall {Wall} slab {Slab} other {Object}}` |
| Number | `{value, number, ::precision-increment/0.001}` |
| Date/time | `{ts, date, ::yyyyMMdd}` and `{ts, time, ::HHmmss}` |
| Unit | `{value, number} {unit}` with unit names from the catalogue |

Rules:

1. No manual pluralization (`count === 1 ? … : …` is prohibited in UI code).
2. Chinese has no plural category, but catalogues must still declare `other` so English can be added safely.
3. Message keys are flat and dot-separated; nesting is discouraged beyond two levels.

Requirement: UI-I18N-03.

## 5. Numbers, Dates, Units

| Context | Format source | Example (zh-CN / en-US) |
|---|---|---|
| Coordinates | `Intl.NumberFormat` with 3 decimals | `1.234` / `1.234` |
| Large counts | Grouping per locale | `1,000` / `1,000` |
| Dates | `Intl.DateTimeFormat`, short | `2026/10/29` / `10/29/2026` |
| Time | 24 h in `zh-CN`, locale default in `en-US` | `14:05:09` / `2:05:09 PM` |
| Units | Display unit system setting | `m` / `m`, `mm` / `mm` |
| Angles | Degree symbol, 1 decimal | `45.0°` |

Rules:

1. Decimal separators follow the locale; stored values never change.
2. Unit switching is a display setting; it must not silently rescale stored geometry.
3. Where a unit is ambiguous (catalog mm vs viewport m), the unit is always shown.

Requirement: UI-I18N-04.

## 6. Pseudo-localization

A pseudo-locale (`en-XA`) expands ASCII by ~40% with accented characters and brackets.

| Check | Pass condition |
|---|---|
| Truncation | No clipped label, button, or tab |
| Overflow | Long words wrap or ellipsize with a tooltip |
| Layout | No overlap at 1280×720 and 1440×900 |
| Concatenation | No sentence built by joining fragments (detectable as broken word order) |
| Requirement | UI-I18N-05 |

Pseudo-localization runs in the visual regression suite at G2.

## 7. Key Convention and Hygiene

```text
<area>.<component>.<element>
  area:      common | shell | tree | props | create | catalog | series | lib | sketch | console | ai | error | a11y
  component: panel or feature name
  element:   label | title | hint | placeholder | action | empty | error
```

Examples: `shell.menu.file.save`, `props.field.length.label`, `error.save.failed.title`.

| Check | Rule |
|---|---|
| Unused keys | Reported per release; removed after one minor version |
| Missing keys | Build fails when a referenced key is absent |
| Duplicate values | Allowed only when semantics differ |
| Key reuse across areas | Prohibited; keys describe context |
| Requirement | UI-I18N-06 |

## 8. RTL Readiness

RTL is not shipped in this cycle, but layout must not block it later.

| Rule | Value |
|---|---|
| CSS | Logical properties only (`margin-inline-start`, not `margin-left`) |
| Icons | Directional icons mirrored via a `data-dir` hook |
| Numbers | Remain LTR within RTL text |
| Viewport | Camera controls unchanged; only chrome mirrors |
| Requirement | UI-I18N-07 |

Enforcement: a style scan flags physical direction properties in new code; legacy exceptions are listed with an expiry date.

## 9. Translation Workflow

| Step | Owner | Output |
|---|---|---|
| 1. Author English source | Frontend | Keys merged with `en-US` values |
| 2. Extract | Script | `i18n/zh-CN.ts` diff with untranslated keys |
| 3. Translate | Translator / domain expert | Updated `zh-CN` values |
| 4. Review in context | Product / discipline lead | Screenshot review of changed screens |
| 5. Verify | CI | Key parity, pseudo-locale, screenshot diff |
| 6. Release note | Frontend | Locale coverage in CHANGELOG |

Rules: translation memory is optional; discipline terminology must follow [GLOSSARY](../../reference/GLOSSARY.md); new terms are added to the glossary before translation.

## 10. Non-Goals

1. Additional locales beyond `zh-CN` and `en-US` in this release.
2. Runtime machine translation.
3. Localized model content or file names.
4. RTL shipping.
