# OmniM 界面安全与隐私

> **契约范围。** 本文固定威胁模型、仅限本机声明、权限门控、路径边界、客户端加固与遥测同意。它是需求 `UI-SEC-01` … `UI-SEC-05` 的规范来源。
>
> **双轨维护义务**：`SECURITY_PRIVACY.zh-CN.md` 是持续维护的译文。在同一次变更中保持章节编号、规则与需求 ID 一致。
>
> **状态。** 设计契约。当前服务端没有鉴权，界面也没有披露这一点。

## 1. 目的与威胁模型

OmniM 运行本地 HTTP 服务与浏览器客户端。现实威胁是：

| 威胁 | 途径 | 缓解 |
|---|---|---|
| 意外暴露到局域网 | 服务绑定 `0.0.0.0` 且无鉴权 | 界面披露 + 文档中的安全默认 |
| 恶意本地页面 | 对本地 API 的 CSRF | Origin 检查、不开放宽松 CORS、CSP |
| 通过打开/保存做路径穿越 | 请求中的构造路径 | 服务端允许根目录校验 |
| 不可信内容注入 | 对象名、IFC 字符串、控制台输出 | 禁止 `dangerouslySetInnerHTML`；处处转义 |
| 数据外泄 | 遥测或诊断 | 选择加入、不含几何、不含名称 |
| 供应链 | npm 依赖 | 锁文件、审计、固定版本 |

## 2. 仅限本机声明

| 界面 | 文案 |
|---|---|
| 首次启动 | 横幅："OmniM 运行无鉴权的本地服务，请勿暴露到网络。" |
| 关于对话框 | 服务绑定地址、鉴权状态、数据目录 |
| 设置 → 安全 | 同样的信息，并提供"复制诊断"操作 |
| 需求 | UI-SEC-01 |

规则：

1. 若服务检测到非回环绑定，界面必须显示持续警告横幅。
2. 本版本不得提供"分享链接""邀请""发布"等操作。
3. 文档与界面必须对此声明保持一致。

## 3. 权限门控

角色是预留的，但现在就要定模型，因为事后把权限补进每条命令的代价很高。

| 角色 | 能力 |
|---|---|
| 查看者 | 读取、选择、测量、剖切、导出 |
| 建模者 | 查看者 + 创建、编辑、删除、保存 |
| 管理员 | 建模者 + 目录/系列编辑、项目设置、诊断 |

规则：

1. 因权限禁用的命令应**隐藏**而非显示为禁用，避免泄露能力细节。
2. 命令注册表带 `requiredRole` 字段；界面在渲染前过滤。
3. 每个变更端点必须在服务端强制；界面门控只是可用性，不是安全边界。
4. 需求：UI-SEC-02。

## 4. 路径边界

| 规则 | 取值 |
|---|---|
| 允许根目录 | 由 `OMNIM_PROJECTS_DIR` 配置（默认 `~/.omnim/projects`） |
| 打开 | 解析符号链接后，路径必须位于允许根目录内 |
| 另存为 | 同一规则；写入前界面显示解析后的路径 |
| 穿越 | `..`、根目录外的绝对路径、UNC 路径以 `OMNI-IO-*` 拒绝 |
| 符号链接 | 解析；逃出根目录的符号链接被拒绝 |
| 最近列表 | 只保留仍解析在根目录内的路径 |
| 需求 | UI-SEC-03 |

## 5. 客户端加固

| 控制 | 规则 |
|---|---|
| CSP | 生产环境：`default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; script-src 'self'` |
| 不可信 HTML | 用户内容禁止 `dangerouslySetInnerHTML`；控制台高亮必须作用于已转义文本 |
| URL 处理 | 禁止 `javascript:` 链接；外链使用 `rel="noopener noreferrer"` |
| 文件 URL | 对象 URL 使用后释放 |
| 依赖 | 提交锁文件；CI 审计；未经评审不得有 post-install 脚本 |
| 密钥 | 客户端包中不得有 API key；AMIR 密钥留在服务端 |
| 需求 | UI-SEC-04 |

## 6. 遥测同意与 PII

| 规则 | 取值 |
|---|---|
| 默认 | 关闭 |
| 同意 | 显式、可撤销，并用平实语言解释收集内容 |
| 收集 | 事件名、耗时、错误码、应用/服务版本、GPU 等级 |
| 不收集 | 几何、对象名、文件路径、用户名、项目内容 |
| 存储 | 同意前仅本地缓冲；拒绝则丢弃 |
| 需求 | UI-SEC-05 |

规则：

1. 同意与许可条款分开；拒绝不得降低功能。
2. 诊断导出由用户主动触发，不属于遥测。
3. 任何新的事件属性都需要在 [TELEMETRY](TELEMETRY.zh-CN.md) §2 记录隐私评审。

## 7. 评审清单

| 项 | 检查时点 |
|---|---|
| 新端点校验路径与角色 | PR 评审 |
| 由用户数据渲染的新字符串已转义 | PR 评审 |
| 新依赖已审计 | PR 评审 |
| 新增资源类型后 CSP 仍通过 | 候选版本 |
| 仅限本机横幅仍准确 | 发布 |
| 遥测事件已过隐私评审 | 发布 |

## 8. 非目标

1. 多用户鉴权与 SSO。
2. 项目文件静态加密。
3. 三个固定角色之外的角色管理界面。
4. 客户端许可证强制。
