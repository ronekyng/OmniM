# OmniM 界面错误码

> **文档定位。** 稳定目录，把界面文案、服务端响应、诊断与遥测连接起来。格式与消息规则见 [FEEDBACK_ERRORS](../specification/ui/FEEDBACK_ERRORS.zh-CN.md) §5。
>
> **双轨维护义务**：`ERROR_CODES.zh-CN.md` 是持续维护的译文。错误码、领域与严重度必须完全一致。
>
> **诚实规则。** 当前代码不产生本文中的任何错误码。现在预留编号，是为了避免实现时各自发明不兼容的编号。

## 1. 错误码格式

```text
OMNI-<AREA>-<NNNN>
  UI   客户端交互与状态
  API  被服务端校验拒绝
  NET  传输与连通性
  IO   文件系统、保存、加载
  GEO  几何校验与内核
  CAT  目录与系列解析
  IFC  导入/导出
  AUTH 鉴权与权限
  SYS  未预期的内部失败
```

规则：错误码永久；退役码继续保留；一个错误码只对应一个消息键与一个严重度。

## 2. 严重度与呈现

| 严重度 | 呈现 | 自动消失 |
|---|---|---|
| 阻断 | 弹窗 | 否 |
| 降级 | 横幅 | 否 |
| 可恢复 | 内联 + 错误提示 | 否 |
| 校验 | 字段内联 | 编辑时 |
| 未预期 | 错误边界 | 否 |

## 11. 维护规则

1. 新错误码必须在本表增行，**并且**在每个语言的词典中有消息键。
2. `scripts/check_ui_contracts.py --errors` 扫描源码与文档；未知错误码让构建失败。
3. 遥测消息不得包含对象名或路径；界面可以包含对象名。
4. 错误码不本地化；周围的消息本地化。
5. 发布后错误码含义不得改变；需要改变时新建一个码。

## 12. 非目标

1. 只用 HTTP 状态码报错。
2. 向最终用户展示堆栈。
3. 按客户划分错误码区间。
