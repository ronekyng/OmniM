# OmniM 前端产品需求

> **文档定位。** 本文是前端的产品需求文档（PRD），用可测试的方式定义界面*必须做什么*。契约（*怎么做*）见 `docs/specification/ui/`，现状见 `docs/status/`。
>
> **双轨维护义务**：`PRD_FRONTEND.zh-CN.md` 是持续维护的译文。在同一次变更中保持章节编号、需求 ID、优先级与门禁列一致。
>
> **单一真值。** 需求 ID 同时登记在 [REQUIREMENTS_REGISTER](REQUIREMENTS_REGISTER.zh-CN.md)。两者冲突时以登记册为准，并修正本文。

## 1. 目的与范围

前端必须从"功能原型"进入"商用工程应用"。范围是 `web/` 下的浏览器客户端，以及项目生命周期所必需的最小服务端端点。

不在范围：后端领域建模、几何内核、IFC 映射、AI 提供方内部实现——那些由各自的规范覆盖。

## 2. 需求约定

| 字段 | 规则 |
|---|---|
| ID | `UI-<AREA>-<nn>`。领域：SHL、DS、INT、FBK、DAT、A11Y、I18N、PRF、CMP、SEC、TLM。永不复用。 |
| 优先级 | `MUST`（阻塞发布）或 `SHOULD`（可延后一个次要版本，但需记录决策）。 |
| 验收 | 不读源码即可观察、可检查。 |
| 门禁 | G0 契约就绪、G1 Alpha、G2 Beta、G3 GA。定义见 [DEFINITION_OF_DONE](../process/DEFINITION_OF_DONE.zh-CN.md)。 |
| 状态 | ✅ 已实现 · 🔀 部分 · 📅 计划 · 💭 提案。与文档图例一致。 |

**追溯规则：** 每条需求至少指名一个验证物（测试文件、扫描脚本、截图集或人工清单）。没有验证物的需求不能过门禁。

## 3. R1 — 外壳与布局

工作区第一眼就要像专业工程软件：区域稳定、状态持久、不用弹层接管视口。

| ID | 需求 | 优先级 | 验收 | 门禁 |
|---|---|---|---|---|
| UI-SHL-01 | 应用必须分三层：项目层、工作区层、编辑器层 | MUST | 项目首页、工作区、各编辑器都有路由 | G1 |
| UI-SHL-02 | 工作区必须有七个固定区域：菜单栏、功能区、左停靠、视口、右停靠、底停靠、状态栏 | MUST | 1440×900 下七区全部可见且不重叠 | G1 |
| UI-SHL-03 | 属性面板必须默认停靠右侧，可调 260–600 px，双击分隔条复位 | MUST | 默认布局下不覆盖视口 | G1 |
| UI-SHL-04 | 左停靠必须用标签页（对象树、轴网、构件库），宽度 240–400 px | MUST | 切换标签不重建视口 | G1 |
| UI-SHL-05 | 底停靠必须默认折叠，展开不超过视口高度 40%，带标签页 | MUST | 控制台、AI、输出、历史均为标签 | G1 |
| UI-SHL-06 | 布局状态必须持久化并可恢复，且提供"重置布局" | MUST | 重启后宽度、标签、折叠状态还原 | G1 |
| UI-SHL-07 | 功能区必须按专业上下文切换，只显示当前域可用命令 | MUST | 切换专业后命令集变化 | G1 |
| UI-SHL-08 | 状态栏必须常驻显示坐标、选中数、单位制、保存状态；帧率必须在开发者模式可用 | MUST | 四项无需刷新即可更新；FPS 在开发者模式显示 | G1 |
| UI-SHL-09 | 面板应支持浮动模式，位置与尺寸可持久化 | SHOULD | 浮动面板重启后回到原位 | G2 |
| UI-SHL-10 | 每个页面必须有标题与面包屑 | MUST | 工作区、构件编辑器、图库、系列页均有标识 | G1 |
| UI-SHL-11 | 宽度低于 1280 px 时停靠必须折叠为图标条，优先保证视口 | MUST | 1024×768 以图标条渲染（降级，不认证） | G2 |
| UI-SHL-12 | 应提供命令面板，作为功能区的键盘替代 | SHOULD | `Ctrl/Cmd+K` 可打开，覆盖全部功能区命令 | G2 |

## 4. R2 — 设计系统与主题

界面必须可换肤、由令牌驱动、保持一致。用户界面代码中的硬编码视觉值是缺陷。

| ID | 需求 | 优先级 | 验收 | 门禁 |
|---|---|---|---|---|
| UI-DS-01 | 令牌必须分三层：原始、语义、组件；组件不得直接消费原始令牌 | MUST | 扫描报告组件中原始令牌引用为零 | G2 |
| UI-DS-02 | 深/浅主题必须通过 `data-theme` 切换且不重载 | MUST | 切换在一帧内生效 | G1 |
| UI-DS-03 | 主题必须默认跟随系统，并持久化用户的显式选择 | MUST | 首次启动遵循 `prefers-color-scheme` | G2 |
| UI-DS-04 | 用户界面样式中不得出现硬编码颜色（令牌文件除外） | MUST | 扫描脚本报告为零 | G2 |
| UI-DS-05 | 语义色必须覆盖 surface/border/text 各角色的默认/悬停/按下/禁用/选中/聚焦六态 | MUST | 双主题下的令牌矩阵完整 | G3 |
| UI-DS-06 | 排版必须使用单一刻度（11/12/13/15/20/28），正文 12–13 px，数值界面用等宽数字 | MUST | 不存在刻度外的字号 | G2 |
| UI-DS-07 | 间距必须基于 4 px（4/8/12/16/24/32），圆角与阴影必须使用既定集合 | MUST | 扫描无刻度外取值 | G3 |
| UI-DS-08 | 必须定义并使用 z-index 分层（视口、覆盖层、停靠、弹窗、提示、调试） | MUST | 不存在越级 z-index | G2 |
| UI-DS-09 | 图标必须使用 16/20/24 px 与 1.5 px 描边；禁止用 emoji 充当图标 | MUST | emoji 图标扫描为零 | G2 |
| UI-DS-10 | 每个交互组件必须定义默认/悬停/按下/选中/禁用/聚焦/加载/错误态 | MUST | 组件状态矩阵无缺口 | G3 |
| UI-DS-11 | 应提供高对比主题，作为可访问性映射而非第三个品牌主题 | SHOULD | 高对比模式下对比度测试通过 | G3 |
| UI-DS-12 | 3D 视口必须有独立的双主题令牌（背景、网格、边线、选中、悬停、剖切、测量） | MUST | 视口配色随主题变化 | G2 |

## 5. R3 — 交互与命令模型

交互必须可预测、键盘完备、不出现浏览器原生弹窗。

| ID | 需求 | 优先级 | 验收 | 门禁 |
|---|---|---|---|---|
| UI-INT-01 | 选择必须支持单击、Ctrl/Cmd 切换、空白取消、框选、Esc 取消 | MUST | 五种手势全部验证 | G1 |
| UI-INT-02 | 拾取必须遵循状态机：idle → configuring → picking → creating → done/error；回车完成、退格撤点、Esc 取消 | MUST | 状态机单测覆盖全部转换 | G1 |
| UI-INT-03 | 快捷键必须来自单一注册表，文档由注册表生成 | MUST | 注册表之外没有组件级全局键盘处理 | G2 |
| UI-INT-04 | 文本框或文本域聚焦时不得触发全局快捷键 | MUST | 在输入框输入 "w" 不会切换工具 | G1 |
| UI-INT-05 | 右键菜单必须按上下文（视口、对象树、属性行）提供命令，且可键盘唤起 | MUST | `Shift+F10` 打开同一菜单 | G2 |
| UI-INT-06 | 对话框必须是一套组件：Esc 关闭、回车确认、焦点陷阱与焦点归还 | MUST | 关闭后焦点回到触发控件 | G2 |
| UI-INT-07 | 破坏性操作必须二次确认，说明影响范围与可逆性 | MUST | 删除父对象前列出受影响子对象 | G2 |
| UI-INT-08 | 撤销/重做必须覆盖全部变更端点；界面必须显示上一步是否可撤销 | MUST | 端点覆盖测试通过；深度 ≥50 | G2 |
| UI-INT-09 | 新建对象必须自动命名 `Type-nnn`，支持重命名与重名检测 | MUST | 连续建十面墙得到 Wall-001…Wall-010 | G1 |
| UI-INT-10 | 单位显示必须一致（视口米、目录毫米），输入框带单位后缀 | MUST | 创建面板中没有无单位数值框 | G2 |
| UI-INT-11 | 双击在每个上下文中必须只有一个已定义含义，且不得触发隐藏的破坏性动作 | MUST | 上下文表发布在 INTERACTION §7 | G2 |
| UI-INT-12 | 视口导航（轨道/平移/缩放）必须可配置，且与视图立方一致 | MUST | 导航设置可持久化 | G2 |

## 6. R4 — 反馈与错误

每个异步或失败的操作都必须自我解释并给出下一步。白屏与原生弹窗都是缺陷。

| ID | 需求 | 优先级 | 验收 | 门禁 |
|---|---|---|---|---|
| UI-FBK-01 | 每个数据驱动面板必须实现加载、空、错误三态 | MUST | 清单覆盖全部面板 | G1 |
| UI-FBK-02 | 加载必须用骨架屏，且 400 ms 内的操作不得闪烁 | MUST | 快速响应不出现加载闪烁 | G1 |
| UI-FBK-03 | 超过一秒的操作必须显示进度，并在安全时提供取消 | MUST | 导入/导出/重建均有进度 | G2 |
| UI-FBK-04 | 每个用户可见错误必须包含错误码、人话原因与恢复动作 | MUST | 错误目录中无未编码条目 | G3 |
| UI-FBK-05 | 禁止使用 `window.alert/confirm/prompt` | MUST | 扫描为零 | G1 |
| UI-FBK-06 | 错误边界必须按路由与面板隔离 | MUST | 单个面板抛错不会让工作区白屏 | G1 |
| UI-FBK-07 | 提示必须分级（成功/信息/警告/错误）；错误提示不得自动消失 | MUST | 错误提示常驻直到关闭 | G1 |
| UI-FBK-08 | 成功反馈必须可关闭，且不得遮挡视口中心 | MUST | 提示位置遵守视口安全区 | G1 |
| UI-FBK-09 | 空状态必须给出下一步动作（创建、导入、示例） | MUST | 每个空状态都有主操作 | G1 |
| UI-FBK-10 | 应可导出诊断包（版本、配置、日志、最近操作，不含几何） | SHOULD | 诊断包不含模型数据 | G3 |

## 7. R5 — 数据完整性与项目生命周期

用户必须始终知道模型在哪、是否已保存、如何恢复。

| ID | 需求 | 优先级 | 验收 | 门禁 |
|---|---|---|---|---|
| UI-DAT-01 | 应用必须从项目首页启动，提供新建、打开、最近、示例 | MUST | 不会隐式把某个项目载入工作区 | G1 |
| UI-DAT-02 | 必须有显式保存（`Ctrl/Cmd+S`）与另存为；保存失败必须保持脏状态并提供重试 | MUST | 保存失败路径有 e2e 覆盖 | G1 |
| UI-DAT-03 | 界面必须显示脏标记与最后保存时间 | MUST | 变更后出现标记，保存后清除 | G1 |
| UI-DAT-04 | 自动保存间隔不得超过 60 秒，且不得阻塞交互 | MUST | 自动保存不掉帧 | G2 |
| UI-DAT-05 | 崩溃后重启必须提供最近自动保存的恢复，损失 ≤5 分钟 | MUST | 杀进程重启演练通过 | G2 |
| UI-DAT-06 | 新建/打开前必须拦截未保存变更，提供保存/放弃/取消 | MUST | 三个分支全部验证 | G1 |
| UI-DAT-07 | 项目元信息（名称、单位、描述、版本）必须可编辑并持久化 | MUST | 重开后取值不变 | G2 |
| UI-DAT-08 | 必须检测项目文件的外部修改；冲突时界面转只读并解释 | MUST | mtime/hash 变化触发该状态 | G3 |
| UI-DAT-09 | 打开时缺失的目录/系列依赖必须明确列出 | MUST | 编辑前显示依赖报告 | G3 |
| UI-DAT-10 | 破坏性操作必须生成可恢复快照 | MUST | 快照恢复能回到先前状态 | G3 |

## 8. R6 — 可访问性

| ID | 需求 | 优先级 | 验收 | 门禁 |
|---|---|---|---|---|
| UI-A11Y-01 | 关键路径必须满足 WCAG 2.2 AA（文本 4.5:1，非文本 3:1） | MUST | axe 在关键路径上零 critical | G2 |
| UI-A11Y-02 | 所有命令必须键盘可达；必须提供快捷键帮助入口 | MUST | 纯键盘可完成主任务 | G2 |
| UI-A11Y-03 | 焦点必须可见、顺序合理、在弹窗内被限制 | MUST | 关闭弹窗后焦点不丢失 | G2 |
| UI-A11Y-04 | 树、属性表、标签页必须暴露 role 与 ARIA 状态 | MUST | 读屏能播报选中与展开状态 | G2 |
| UI-A11Y-05 | 纯图标按钮必须有无障碍名称；视口必须提供文本替代 | MUST | 无障碍树中无未命名按钮 | G2 |
| UI-A11Y-06 | 必须遵循 `prefers-reduced-motion`，关闭非必要动画 | MUST | 开启后过渡动画消失 | G3 |
| UI-A11Y-07 | 由 UI-DS-11 定义的高对比主题应在所有界面文本上达到 AA | SHOULD | 对比度审计通过 | G3 |
| UI-A11Y-08 | 操作结果与选中变化必须通过 `aria-live` 播报 | MUST | 读屏能播报创建/删除/保存 | G3 |

## 9. R7 — 国际化

| ID | 需求 | 优先级 | 验收 | 门禁 |
|---|---|---|---|---|
| UI-I18N-01 | 100% 用户可见字符串必须外置；源码中除词典外不得出现中文字面量 | MUST | 字符串扫描为零 | G2 |
| UI-I18N-02 | 默认语言 `zh-CN`，回退 `en-US`；切换无需重载 | MUST | 两种语言均完整渲染 | G2 |
| UI-I18N-03 | 复数与选择必须使用 ICU MessageFormat | MUST | 两种语言的复数分支验证通过 | G2 |
| UI-I18N-04 | 数字、日期、单位必须遵循当前语言环境；单位制可切换 | MUST | 1,000.5 与 1.000,5 均正确 | G2 |
| UI-I18N-05 | 伪本地化构建必须通过，无溢出或截断 | MUST | 伪语言截图评审通过 | G3 |
| UI-I18N-06 | 键名必须遵循 `area.component.key`；应检测未使用键 | SHOULD | CI 输出未使用键报告 | G3 |
| UI-I18N-07 | RTL 布局应在结构上可行（逻辑属性，不写死 left/right） | SHOULD | 扫描无物理方向 CSS | G3 |

## 10. R8 — 性能

预算与参考机定义见 [PERFORMANCE](../specification/ui/PERFORMANCE.zh-CN.md)，下表是产品级摘要。

| ID | 需求 | 优先级 | 验收 | 门禁 |
|---|---|---|---|---|
| UI-PRF-01 | FCP ≤1.2 s P95；FMP ≤2.5 s P95；工作区就绪 ≤4 s | MUST | 性能夹具报告在预算内 | G2 |
| UI-PRF-02 | 交互反馈 ≤100 ms；面板切换 ≤150 ms | MUST | 交互追踪在预算内 | G2 |
| UI-PRF-03 | 2000 构件下视口 ≥30 fps；500 构件目标 60 fps | MUST | 帧时间夹具 | G2 |
| UI-PRF-04 | 空闲 CPU <1%（按需渲染） | MUST | 60 秒空闲采样 | G2 |
| UI-PRF-05 | 5000 构件下内存 ≤1.5 GB，8 小时会话无增长 | MUST | 内存浸泡测试 | G3 |
| UI-PRF-06 | 首屏 JS ≤500 KB gzip，按路由分包 | MUST | 包体报告 | G2 |
| UI-PRF-07 | 对象树 5000 节点滚动 ≥50 fps（虚拟化） | MUST | 滚动追踪 | G3 |
| UI-PRF-08 | 性能相对基线回退超过 ±10% 必须让 CI 失败 | MUST | CI 门禁 | G3 |

## 14. 追溯与变更控制

- 每个需求 ID 必须在 [REQUIREMENTS_REGISTER](REQUIREMENTS_REGISTER.zh-CN.md) 中恰好出现一行，含契约、验证、门禁与状态。
- 修改需求需要：改本文、改登记册、改契约，并在 [CHANGELOG](../status/CHANGELOG.zh-CN.md) 记录。
- 删除需求必须标记 `Superseded by UI-XXX-nn`；ID 永不删除。
- 未经记录决策，需求不得提前门禁。

4. 云端多人临场、评论或协同编辑。
5. 深色、浅色、高对比之外的换肤。
