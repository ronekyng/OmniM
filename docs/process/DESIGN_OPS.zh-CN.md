# OmniM 设计运营

> **文档定位。** 前端设计系统与 UI 契约的治理：谁决策、什么需要评审、组件与令牌如何演进、变更如何保持可追溯。
>
> **双轨维护义务**：`DESIGN_OPS.zh-CN.md` 是持续维护的译文。角色、变更等级与生命周期状态必须一致。
>
> **状态。** 设计契约。项目很小，同一人可能承担多个角色，但职责必须明确。

## 1. 目的

没有治理，设计系统就只是建议。本文让变更可评审，又不至于把小团队变成委员会。

## 2. 角色与 RACI

| 活动 | 产品 | 设计 | 前端 | QA | 文档 |
|---|---|---|---|---|---|
| 需求定义 | **A/R** | C | C | I | I |
| 外壳/信息架构契约 | A | **R** | C | I | C |
| 设计系统契约 | I | **A/R** | C | I | C |
| 交互契约 | C | **A/R** | C | C | I |
| 实现 | I | C | **A/R** | C | I |
| 验证证据 | I | C | R | **A** | I |
| 发布门禁签字 | **A** | C | R | R | C |
| 文档 | C | C | C | I | **A/R** |

R = 负责执行，A = 最终问责，C = 需咨询，I = 需知会。

## 3. 变更等级

| 等级 | 示例 | 评审 | 通知 |
|---|---|---|---|
| **编辑性** | 错别字、措辞、链接修复 | 文档责任人 | 无 |
| **次要** | 新组件状态、既有角色下的新令牌、新 e2e 测试 | 设计 + 前端 | 变更日志 |
| **重大** | 新契约章节、新外壳区域、主题模型变更 | 设计评审 + 必要时 RFC | RFC 或 ADR |
| **破坏性** | 移除组件、重命名令牌、修改快捷键 | RFC + 迁移说明 + 废弃期 | 发布说明 |

规则：拿不准就向上归类。影响肌肉记忆的"次要"变更其实是重大。

## 4. 设计评审

| 触发 | 必需产物 | 决策窗口 |
|---|---|---|
| 新面板或外壳区域 | 线框图、状态表、截图 | 2 个工作日 |
| 新组件 | 状态矩阵、使用的令牌、可访问性说明 | 2 个工作日 |
| 令牌变更 | 前后截图、对比度检查 | 1 个工作日 |
| 导航或快捷键变更 | KEYBOARD_MAP 差异、迁移说明 | 2 个工作日 |

评审输出记录为：通过、有条件通过、驳回。条件必须带责任人与日期。

## 5. 组件生命周期

```text
提议 → Alpha → 稳定 → 废弃 → 移除
```

| 状态 | 含义 | 允许进生产 |
|---|---|---|
| 提议 | 仅文档 | 否 |
| Alpha | 已实现，API 可能变化 | 仅限开关后 |
| 稳定 | 完整状态矩阵、已测试、有文档 | 是 |
| 废弃 | 已有替代；已排定移除 | 是，但带警告 |
| 移除 | 废弃期后删除 | — |

组件不得从"提议"直接跳到"稳定"，至少需要一个波次的 Alpha 期。

## 6. 令牌与契约版本

| 产物 | 版本方式 | 破坏性变更 |
|---|---|---|
| `tokens.css` | 文件头 Semver 注释 | 重命名或移除令牌需一个次要版本的废弃别名 |
| UI 契约（`specification/ui/*`） | front matter 中的文档版本 | 需要 RFC |
| 组件 API | 组件模块内 Semver | 主版本升级并附 codemod 或迁移说明 |
| 需求 ID | 永久 | 永不重命名，只标记取代 |

## 7. 决策记录

| 决策类型 | 记录位置 |
|---|---|
| 跨模块架构 | [DECISIONS](../architecture/DECISIONS.zh-CN.md) 中的 ADR |
| 开放设计取舍 | [RFC](../RFC/README.zh-CN.md) |
| 需求取舍 | `DEFINITION_OF_DONE` 例外 + 发布说明 |
| 视觉例外 | 带责任人与到期日的行内注释，并登记债务 |

## 8. 节奏与指标

| 活动 | 节奏 |
|---|---|
| 契约评审 | 每个波次 |
| 成熟度重评 | 每个门禁 |
| 视觉基线刷新 | 每个候选版本 |
| 可访问性审计 | 每个门禁 |
| 设计债务分诊 | 每月 |

跟踪指标：需求覆盖率、成熟度分数、硬编码颜色数、字符串外置率、组件状态完整度、可访问性 critical 数。

## 9. 非目标

1. 独立的设计系统团队。
2. 公开的组件市场。
3. 在仓库工具中实现审批流。
