# OmniM 发布与支持清单

> **文档定位。** 填补 G3 的空白：从"构建通过"到"客户能安装、迁移并得到支持"。定义发布说明格式、迁移与回滚流程、支持运行手册与已知问题登记。
>
> **双轨维护义务**：`RELEASE_CHECKLIST.zh-CN.md` 是持续维护的译文。章节编号与清单项必须一致。
>
> **状态。** 设计契约。尚未有版本按本清单执行过发布。

## 1. 目的与范围

商用发布除构建产物外还需要四份材料：改了什么、如何从上一版本迁移、坏了怎么办、已知哪些问题。本文定义这四份材料及证明其存在的签核。

不在范围：市场材料、定价、应用商店上架。

## 2. 发布说明模板

每个构建随附；存入发布记录，并在"关于"对话框中链接。

```markdown
# OmniM <version> (<date>)

## 亮点
- <一到三条用户可见结果>

## 新增
- <功能>（<需求 ID>）

## 变更
- <行为变化> —— <影响谁>

## 修复
- <缺陷>（<issue 链接>）

## 已知问题
- <问题> —— <临时方案>

## 兼容性
- 项目模式：<版本>；可被 <应用版本> 读取
- 服务端 API：<兼容的客户端版本>
- 浏览器：<矩阵引用>

## 升级说明
- <步骤，或"无">
```

规则：

1. 每条写用户可见结果，不写文件名。
2. 附需求 ID 以便追溯。
3. 破坏性变更放在**升级说明**，绝不埋在**变更**里。
4. 已知问题链接到 §5 的登记。

## 3. 迁移与回滚

| 情况 | 要求 |
|---|---|
| 项目模式未变 | 发布说明写"无需迁移" |
| 模式新增字段 | 向前兼容读取；旧应用以 `OMNI-IO-0006` 拒绝更新模式 |
| 模式语义改变 | 提供迁移命令或明确拒绝；绝不静默重解释 |
| 服务端 API 变化 | 发布说明给出客户端/服务端兼容表 |
| 回滚 | 上一版本必须能打开新版本写出的文件，或说明降级路径 |

规则：

1. 模式升级没有迁移路径即为发布阻塞项。
2. 迁移前在项目旁写备份（`<name>.omnim.bak`）。
3. 迁移必须幂等，并报告影响的对象数。
4. 迁移后的回滚依赖备份；界面必须在迁移前说明。

## 4. 支持运行手册

| 场景 | 第一步 | 升级处理 |
|---|---|---|
| 应用无法启动 | 检查服务可达性、端口、`OMNIM_PROJECT` | 收集诊断包 |
| 模型加载失败 | 检查模式版本、依赖报告、恢复快照 | 索取项目与依赖清单 |
| 保存失败 | 检查路径根、权限、磁盘空间、外部修改 | 收集诊断 + 服务日志 |
| 崩溃或白屏 | 索取诊断包与最后操作 | 用夹具项目复现 |
| 渲染异常 | 检查 WebGL2 支持与 GPU 驱动 | 对照兼容矩阵 |
| 性能回退 | 索取对象数、浏览器、GPU 等级 | 与基线夹具对比 |

规则：

1. 未经用户同意且数据非机密时，支持不得索取项目文件。
2. 每个工单记录应用版本、服务版本、操作系统、浏览器、GPU 与错误码。
3. 每个版本用一张合成工单演练一次运行手册。

## 5. 已知问题登记

| 字段 | 规则 |
|---|---|
| ID | `KI-<年份>-<nn>` |
| 摘要 | 一句话，用户语言 |
| 影响 | 有临时方案 / 无临时方案 |
| 影响版本 | 范围 |
| 临时方案 | 具体步骤或"无" |
| 目标修复 | 版本或"未排期" |
| 责任人 | 具名 |

规则：登记随版本发布；关闭后移入变更日志；每个门禁评审一次。

## 6. 版本与兼容性声明

| 声明 | 来源 |
|---|---|
| 应用版本与构建哈希 | 构建元数据 |
| 项目模式版本 | `Project.schema_version` |
| 服务端 API 兼容性 | 客户端/服务端表 |
| 浏览器与 GPU 矩阵 | [COMPATIBILITY](../specification/ui/COMPATIBILITY.zh-CN.md) §2 |
| 可访问性一致性 | [A11Y](../specification/ui/A11Y.zh-CN.md) §10 |

"关于"对话框显示前四项；发布说明显示全部五项。

## 7. 签核清单

- [ ] 按模板写完发布说明。
- [ ] 迁移路径已做前向与后向测试。
- [ ] 用备份文件测试过回滚。
- [ ] 支持运行手册场景演练过一次。
- [ ] 已知问题登记已发布。
- [ ] 兼容性声明已更新。
- [ ] 诊断导出已验证不含几何。
- [ ] 已链接 CHANGELOG。
- [ ] 门禁责任人已签字（[RELEASE_READINESS](../status/RELEASE_READINESS.zh-CN.md)）。

## 8. 非目标

1. 自动化应用商店分发。
2. 应用内更新推送。
3. 客户专属发布分支。
