# RFC-0002：界面外壳与设计系统

- **状态**：草案
- **相关**：[IA_SHELL](../specification/ui/IA_SHELL.zh-CN.md) · [DESIGN_SYSTEM](../specification/ui/DESIGN_SYSTEM.zh-CN.md) · [INTERACTION](../specification/ui/INTERACTION.zh-CN.md) · [PRD_FRONTEND](../product/PRD_FRONTEND.zh-CN.md)

## Summary

用停靠式、令牌驱动、双主题的工作区取代当前临时拼装的前端外壳，并把界面当作有版本契约，而不是一堆面板。本提案覆盖四个相互耦合的决策：外壳架构、主题模型、组件治理、需求追溯。

## Motivation

前端能执行真实建模操作，但读起来不像商用软件。实测证据（2026-10-29）：

- 属性面板默认是居中浮层（`appStore.ts:89`），选中对象就遮住视口。
- 主样式表有 712 处硬编码颜色（全部 CSS 731 处），绕过了被声明两次的令牌系统。
- 31 个文件中有 858 段中文，没有 i18n 层；63 处 emoji，其中 25 处当图标。
- 五处原生浏览器弹窗；零个错误边界；没有保存界面，客户端对保存端点的调用为零。
- 可访问性基本缺失（1 个 `aria-*`、0 个 `role`）。

这不是一次样式美化能修好的：外壳、主题模型与发布流程必须一起改。

## Detailed Design

### 1. 外壳

七个固定区域（菜单栏、功能区、左停靠、视口、右停靠、底停靠、状态栏）。停靠与视口是兄弟关系，可调宽、带标签、可折叠，并按用户持久化。浮动模式只作为逃生通道存在。

### 2. 主题

三层令牌（原始 → 语义 → 组件），根元素使用 `data-theme`。深色与浅色是产品主题；高对比是可访问性映射。3D 场景从同一主题派生的视口调色板取值；渲染代码中不得出现主题判断。

### 3. 组件

组件只有具备完整状态矩阵（默认、悬停、按下、选中、禁用、聚焦、加载、错误）、只用语义令牌、可键盘操作且有可访问性契约时才可交付。禁止用 emoji 充当图标。

### 4. 需求与追溯

11 个域、96 条需求；每条一个 ID、一个契约锚点、至少一个验证物、一个门禁、一个状态。登记册是单一真值；契约与状态文档引用 ID，而不是复述需求。

### 5. 项目生命周期

应用增加项目层（`/projects`）、显式保存与另存为、脏跟踪、写入恢复文件的自动保存、崩溃恢复、外部变更检测与依赖报告。这需要新的服务端端点与可变的 `save_path`；最小契约见 [DATA_INTEGRITY](../specification/ui/DATA_INTEGRITY.zh-CN.md) §8。

## Compatibility

| 范围 | 影响 |
|---|---|
| 现有路由 | 工作区仍为 `/`；编辑器不变；新增 `/projects` |
| 现有面板 | 注册 API 扩展图标/宽度/标签元数据，向后兼容 |
| 现有快捷键 | 保留现有绑定；新增保存、命令面板、帮助 |
| 项目文件 | 界面工作不要求模式变更 |
| 服务端 API | 新增四到六个端点；既有端点不变 |
| 文档 | 既有文档增加引用，不做重写 |

## Alternatives

| 替代方案 | 否决原因 |
|---|---|
| 保留浮动面板只做美化 | 解决不了视口遮挡与布局持久化 |
| 单一主题（仅深色） | 产品否决；办公投影与打印需要浅色 |
| 采用 CSS-in-JS 组件库（如 MUI） | 引入大依赖且与工程密度要求冲突；令牌加自有基础组件更小 |
| 用命令面板取代功能区 | 键盘用户受益，但偶发用户的可发现性下降；本提案保留功能区并增加命令面板 |
| 先重写渲染器 | 渲染器是最强的部分；产品化瓶颈在外壳、生命周期与反馈 |

## Non-Goals

1. 公开组件库或插件 SDK。
2. 移动端或触屏优先布局。
3. 替换 three.js 或几何内核。
4. 云端协作界面。
