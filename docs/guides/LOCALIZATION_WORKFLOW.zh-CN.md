# OmniM 本地化流程

> **文档定位。** [I18N_L10N](../specification/ui/I18N_L10N.zh-CN.md) 背后的操作流程：谁提取、谁翻译、如何评审、什么阻塞发布。
>
> **双轨维护义务**：`LOCALIZATION_WORKFLOW.zh-CN.md` 是持续维护的译文。步骤、角色与检查项必须一致。
>
> **状态。** 设计契约。代码库中目前没有字符串词典，也没有翻译管线。

## 1. 目的

把翻译当成最后一刻的导出，必然失败。本流程让本地化成为持续、可检查、有明确交接的活动。

## 2. 角色

| 角色 | 职责 |
|---|---|
| 字符串作者（前端） | 添加键、英文源与上下文说明 |
| 术语负责人（产品 / 专业负责人） | 在术语表中批准新术语 |
| 译者 | 产出专业准确的 `zh-CN` 取值 |
| 评审者 | 在上下文中核对含义与界面适配 |
| 发布负责人 | 在门禁前确认语言覆盖 |

同一人可以承担多个角色，但交接仍要以书面形式发生。

## 3. 字符串生命周期

```text
编写（en-US）→ 同次变更加入（zh-CN）→ 上下文截图 → 评审 → 合并
      │                                                    │
      └── 后续变更：在同一提交中更新两种语言 ───────────────┘
```

| 阶段 | 产物 | 规则 |
|---|---|---|
| 编写 | 带上下文说明的 `en-US` 条目 | 组件中不得有字面量 |
| 初译 | `zh-CN` 条目 | 同键、同占位符 |
| 上下文 | 变更界面截图 | 布局不同时两种语言都要 |
| 评审 | 评审者签字 | 检查术语一致性 |
| 合并 | 含两种语言的单个提交 | 缺失对应项让 CI 失败 |

## 4. 翻译交接

| 字段 | 必需 |
|---|---|
| 键 | 按作者定义 |
| 英文源 | 完整句子，不是片段 |
| 上下文说明 | 出现在哪里、含义是什么 |
| 占位符 | 列出类型与示例 |
| 截图 | 可选，新界面优先 |
| 术语 | 含领域术语时给出链接 |

交接格式：`en-US` 词典的 diff 加上上述上下文表。仓库中不使用电子表格。

## 5. 术语

1. 新的领域术语必须**先**加入 [GLOSSARY](../reference/GLOSSARY.zh-CN.md)（两种语言），才能在界面中使用。
2. 同一概念在各面板使用同一术语；评审中拒绝同义词混用。
3. 单位符号不翻译（`m`、`mm`、`°`）。
4. 自动命名中的对象类型前缀按契约保持 ASCII（[INTERACTION](../specification/ui/INTERACTION.zh-CN.md) §9.1）。

## 6. 评审

| 检查 | 是否阻塞 |
|---|---|
| 两种语言的键对齐 | 是 |
| 占位符对齐与类型 | 是 |
| 伪语言布局通过 | G2 起为是 |
| 术语与术语表一致 | 是 |
| 语气符合产品声音（直接、无营销腔） | 是 |
| 变更界面截图评审 | 新界面为是 |

## 7. 发布清单

- [ ] `zh-CN` 与 `en-US` 的键齐全。
- [ ] 未使用键不超过约定阈值。
- [ ] 伪语言截图已评审。
- [ ] 语言切换无需重载。
- [ ] `<html lang>` 正确更新。
- [ ] 数字、日期与单位遵循语言环境。
- [ ] CHANGELOG 注明语言覆盖与新术语。

## 8. 工具

| 工具 | 用途 | 状态 |

## 9. 非目标

1. 集成翻译管理系统。
2. 把机器翻译作为发布路径。
3. 为每个字符串在仓库保存本地化截图。
